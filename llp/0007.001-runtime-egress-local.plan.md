## Integration layers

The source integration is split into dependent review layers
[inferred: implementation split following Gabe's staged-integration direction]:

1. **Native guard and policy control.** Keep the shared-page protocol, covered
   operations and regression tests together. Preserve the failed historical
   performance result. Policy publication continues to report `drained: false`;
   it cannot admit a job that requires enforcement.
2. **Capability loader and boot lifetime.** Add an explicit startup-only
   `allProcesses` scope without changing existing app scopes or deferred loading.
   Read the guard's immutable policy path through startup capability configuration.
   Retain that startup record, image and page through disable and session release,
   so later helpers discover the same page. Reuse launch state, the exact-device
   lock and resource rollback. Enrollment binds to the Simulator launchd PID and
   native start time, not the host boot UUID; revalidate it under the lock.
   Add packaging/build source entries, with native builds separately coordinated.
3. **Initial CLI controls and readiness.** Register `egressGuard`, normalize the
   existing enable/disable flags, and require an explicit warmup policy for resident
   preparation. Check resident artifacts and control state before reporting warm
   readiness. Required enforcement checks run before app actions or ready output.
4. **Private adoption.** Carry the normalized policy through the existing strict
   session configuration and one-shot claim. Reject boot injection and unrelated
   capability changes. Verify the selected device's boot, artifact and mapping
   identity before changing policy; retain consumed-once ownership and original
   plus cleanup errors.

Focused tests must exercise config parsing and startup scope, stable mapping
lifetime, actual CLI startup ordering, and the private adoption handler. They must
assert rejection before ready/app actions when enforcement cannot be established.
Controller tests remain a separate check of one process's observed mode.

Two missing checks prevent a published mode from becoming an admission result:
coverage of the selected `launchd_sim` tree, including helpers, and quiescence of
calls admitted during pass-through. A new-process probe or page generation proves
neither. Until those checks exist, the integrated block-admission path must fail
closed; no caller-provided validation flag can bypass it. A native in-flight
protocol needs its own failure and cost review. A boot that has provably remained
blocked avoids prior pass-through calls only for that boot; it does not establish
arbitrary off-to-on reuse [inferred: minimum enforcement requirements].

## Explicit warmup policy

Initial startup derives the immutable `egressWarmupPolicy` from the explicit
capability choice: `--enable egressGuard` means `block`, and
`--disable egressGuard` means `passthrough`. There is no separate public warmup
flag and no default. A prepared `--orphan` session makes this choice before job
intent is known; adoption requires its own explicit job choice. Startup without
either flag remains uninstrumented. The local tests exercise both initial modes
[inferred: input mapping under the accepted integration plan; observed: no
production warmup policy selected].

- With warmup `passthrough`, the page explicitly starts in pass-through. A local
  egress job requests block; an ordinary job requests pass-through.
- With warmup `block`, the page explicitly starts in block. A local egress job
  retains block; an ordinary job explicitly requests pass-through.
- Teardown must restore the selected warmup policy in the agreed cleanup order;
  removing a capability record does not unload a resident image.
- Missing, malformed or incompatible control state is an error. The guard must
  never interpret broken state as explicit pass-through. Before reporting warm
  readiness, warmup must self-check the resident image and control page. Failure
  means **no warm session and cold fallback**, never ready with broken normal-job
  networking. The current source rejects egress startup before boot while native
  image self-check and enforcement validation remain unavailable.

These are candidate semantics, not a production warmup selection
[inferred: proposed contract; observed: coordinator's failure/readiness requirement].

## Cost model and performance gates

Every covered call first loads the shared atomic policy word. Explicit
pass-through calls the original immediately: no fd lookup, disk read, allocation
or logging. Block mode uses `getpeername` for destination-less send/write calls;
non-sockets, Unix sockets and loopback pass through. There is no per-fd cache,
so no cache entry can survive close, dup or descriptor reuse. This avoids cache
lifecycle machinery but adds a syscall to file writes in block mode. Concurrent
descriptor replacement between peer inspection and use remains a limit
[inferred: proposed cost model and coverage limit].

Benchmark file writes and connected socket sends in paired rounds with: no guard,
today's EAS guard, resident pass-through, and resident block. Keep the payload,
iterations and local peer behavior identical. Report per-call times and paired
differences; do not claim a speed result from one timing sample. Test-only denied
loopback classification is excluded from performance runs.

Normal jobs must not measurably regress versus no guard. Egress jobs must not
measurably regress versus today's guard either; today's guard does not inspect
`write`/`writev`. A measurable regression is a **stop/revise gate** for runtime
admission, release and promotion; held source integration may continue. Resident
wrappers have some unavoidable branch/load cost; these
requirements are not satisfied by claiming that source looks cheap
[observed: coordinator relayed Gabe's performance rule and required the baseline comparison].

## Covered operations and transition result

The candidate covers `connect`, `connectx`, `send`, `sendto`, `sendmsg`, `write`,
`writev`, and their relevant NOCANCEL entries. Reuse EAS's destination
classification. Existing connected TCP/UDP sends must inspect the peer when
blocked. Tests verify both behavior and that ordinary loopback/file IO survives.

The local control result reports a **published generation** only. A call that
sampled pass-through before publication may finish afterward; publication does
not drain existing calls. All-process enforced/drained acknowledgement remains
an integration gate. Do not enable warm local-egress admission from this result.

Not covered: raw syscalls; `sendfile` and `sendmsg_x` until explicitly implemented
and tested; other interposers introduced with late `dlopen`; processes that did
not preload the guard; processes outside the Simulator, including serve-sim,
the worker and chisel; concurrent fd replacement between check and use. Android
retains its separate fence. Host tests are **macOS host mechanism only**
[inferred: declared coverage boundary].

## Native argument handling

Addressed sends must check the actual connected peer as well as the supplied
destination: established TCP can ignore a decoy destination and transmit through
its existing peer. An unresolved Internet stream peer must also block: its
handshake can complete after inspection and before the send. Only addressed
datagrams can use the supplied destination without a resolved peer. A test-only
interposer models that pending-peer observation deterministically; it is not a
real handshake or Simulator proof. This conservative rule also refuses unresolved
loopback streams until their peer is available [observed: native guard and host
regression fixture].
`connectx` must classify an `AF_UNSPEC` UDP destination;
unlike `connect`, that call can translate it into an IPv4 connect-and-send
[observed: pinned XNU `tcp_usrreq.c`, `uipc_syscalls.c`, `udp_usrreq.c`; local
loopback regression probes reproduced delivery before correction, 2026-10-26].

Mapped-IPv6 TCP also accepts short socket addresses. The guard must classify the
zero-filled effective address rather than require all scope-id bytes. Host
probes reproduced four denied loopback-test connections at lengths 24–27 before
correction; a normal-classifier loopback control remains accepted. The tested
short IPv4 shapes are kernel-rejected, not claimed as a reproduced bypass
[observed: XNU `uipc_syscalls.c` `getsockaddr_s` and bounded host regression].

The local guard now copies inspected caller structures using bounded
`vm_read_overwrite` calls before reading them. This is a libSystem Mach
operation, not a framework dependency. Unreadable syscall structures return
`EFAULT` instead of faulting in the guard. The original EAS guard also directly
dereferences those pointers; this is a corrected guard weakness, not a claim
of a new production regression [observed: native source and host child tests].
The guard uses the Simulator-supported Mach API from `<mach/mach.h>`; the
Simulator SDK rejects `<mach/mach_vm.h>`. Compile-only guard builds pass against
SDKs 26.4 and 27.1 and link only libSystem. This is compilation evidence, not a
Simulator execution result [observed: isolated clang builds, 2026-10-27].

The host runner creates its own fresh private directory and never accepts a
caller work directory for recursive cleanup. Its baseline behavior fixture uses
a private test-only cached-mode setter: establish sockets in log mode, enable
actual blocking, verify a new connection is refused, then test the old sockets.
The performance baseline remains an unmodified copy of today's guard with its
real block mode and destination classification [observed: `tests/run.py`].

A separate fixture now changes policy through the real controller while the same
guarded process retains its original TCP/UDP sockets. It observes
pass/block/pass/block behavior after each publication. That is one process's host
observation, not all-process observation or a drain acknowledgement
[observed: controller integration fixture]. Simulator execution and its actual
device/Xcode details remain an open review gate; this draft does not satisfy the
repository's native Simulator evidence requirement [observed: package AGENTS and
the retained validation scope].

## Progress

The native guard and reproducible host runner live in
`Sources/ServeSimEgressGuard/` (package-relative). Build/package definitions,
registration and initial CLI wiring exist in source, but admission is held and
the new native integration is unbuilt. Tests first failed against a private copy of today's guard. The
guard then passed live transitions on old TCP/connected UDP, five send APIs,
NOCANCEL entries, connectx, dup/fd reuse, Unix/file IO, invalid control state,
explicit warmup selection and concurrent controller publication
[observed: Codex host tests, macOS 26.6.2 arm64, Apple clang 21.0.0, 2026-10-26].

**Stop/revise: block-mode cost missed the gate.** In 21 randomized paired host
rounds, block versus today's guard added a median paired 162.682 ns to regular
file `writev` (bootstrap 95% interval 62.670–235.471 ns), 125.469 ns to `/dev/null`
`write` (118.515–135.003 ns), and 1038.909 ns to connected UDP `send`
(672.833–1237.300 ns). Regular file `write` was noisy. Pass-through versus no
guard intervals crossed zero in this run; this is not evidence of zero cost or
normal-job acceptance. Timings describe this host microbenchmark, not actual EAS
jobs or iOS Simulator performance
[observed: Codex host benchmark, 2026-10-26; raw samples/logs outside git].

The benchmark used the initial implementation; subsequent self-review corrected an
unresolved internet peer, and adversarial review corrected addressed-send,
`connectx` and unreadable-pointer handling plus test-runner issues. Corrected-source
behavior tests passed. Benchmarks were not repeated after those changes:
the approach had already failed the integration gate, so no speed claim is made
for the corrected source [observed: Codex tests and source, 2026-10-26].

The initial cost result still blocks enabling or promoting the integrated path.
Held source integration may continue under the staged plan above. A cheaper approach needs
design review before further implementation; a per-fd cache would need correct
close/dup/descriptor-transfer/reuse handling rather than a blind optimization.
The native guard omits EAS event reporting, and shared-page unlink/truncation,
boot identity, fork behavior and all-process drain remain unvalidated integration
conditions. Host binaries were confined to private temporary directories, removed
after results were retained externally. No Simulator or hosted proof exists.

## Native helper contract checks

The boot probe enumerates only the current UID. A process that disappears during
inspection may be skipped, but an unreadable own-user process still fails the
probe with its PID and error; unknown visibility does not establish absence. A
host contract test runs the real controller and probe, plus deterministic
visibility failures, in a fresh private temporary directory. The unused-UUID
probe returns `null` without requiring root [observed: native helper source and
`egress-native.test.ts`, 2026-10-27].

The guard compiles for Simulator SDKs 26.4 and 27.1; the host helpers and loader
parser checks also pass locally. These results do not validate boot matching,
process coverage or policy transitions in an actual Simulator. No package build,
Simulator execution, hosted acceptance or new performance measurement is claimed
[observed: bounded native checks and retained integration gates].

## Resident operation boundaries

The required startup path boots only its prepared enrollment, rejects an
already-booted result, and checks the same native identity after waiting. It
retains assets on cancellation or uncertain boot failure. Serve-sim camera injection and
shutdown/reboot operations, including preview-grid shutdown, that cannot preserve enrollment are refused before
changes. These checks do not provide the missing all-process/drain protocol,
choose a warmup default or reclaim a dead boot [observed: strict boot and
operation preflights; native execution remains separately gated].

UDID normalization and controller-result validation are shared small helpers.
Boot observation is named for its actual purpose; required identity checks stay
at asynchronous readiness boundaries. Preboot config publication is atomic and
last, so failure restores enrollment metadata without an unreachable config
rollback [observed: launch-state helpers, resident resources and rollback fixture].
